Architecture

Buy the model. Own the item bank and the verification layer. The single architectural commitment everything else follows from is that the model never chooses what it is grounded in: retrieval happens before generation, deterministically, so the set of permitted sources is known before a word is produced and can be checked against afterwards.

The turn pipeline

The load-bearing property: the model never retrieves. The composer selects the permitted sources deterministically from the objective before generation begins. The model is given those sources and cannot reach outside them, so the set to check against is known in advance rather than reconstructed from whatever the model decided to look at.

session state
      |
      v
[1] COMPOSER            deterministic, no model call
      |  selects objective from the learner's mastery model
      |  retrieves the objective's required item-bank nodes (k bounded)
      |  renders the style card from the preset object  (cine.card/1.0.0)
      |  assembles turn plan: objective + permitted sources + card + window
      v
[2] GENERATOR           model call, pinned version
      |  produces a turn with an inline citation on every substantive assertion
      v
[3] VERIFIER            four checks, all blocking
      |  a. citation presence   every substantive assertion cites a permitted node
      |  b. claim support       the assertion is entailed by the node it cites
      |  c. scope              nothing outside the declared specification scope
      |  d. mathematics        every symbolically checkable step, checked by CAS
      v
[4] GATE
      |-- pass --> render to learner --> log turn record
      |-- fail --> fallback turn (validated item verbatim) --> log + adjudication queue
      v
[5] LOGGER              turn record: citations, verdicts, extracted style signatures

Three consequences worth making explicit, because each one is a property that would be lost by a more conventional design.

  • Grounding is decided before generation, not inferred after it. An architecture where the model calls a search tool cannot tell, afterwards, whether a claim came from a retrieved document or from the model's own weights. Ours can, because the permitted set is fixed at step 1.
  • The fallback needs no model. Step 4's failure path serves examiner-written material directly from the bank. That is why the item bank is authored as standalone readable material, per 03: validated-item-only mode has to be a usable product, not a stub.
  • Style cannot reach the content plane. The style card is an input to step 2 only. It is not visible to step 1's retrieval or to step 3's checks. That is what makes T-STY-03, style changes the teaching and never the truth, an architectural property rather than a hope.

The verifier, which is the product

Promise P2 in 01 is the business. The verifier is the thing that keeps it, so it gets specified rather than described.

CheckMechanismFailure action
a. Citation presenceDeterministic parse. Every sentence classified as a substantive curricular assertion must carry a citation to a node in the permitted set.Block. This is a format failure and is cheap to detect.
b. Claim supportEntailment check of the assertion against the cited node. A model call, on a pinned cheaper model, with the node and the assertion only.Block, and queue for human adjudication. Every automated failure is adjudicated, which is what makes T-GND-01 measurable rather than self-reported.
c. ScopeClassifier against the declared objective set.Block. The learner sees the refusal in 01.
d. MathematicsComputer algebra system on every symbolically checkable step. Deterministic, local, no model call.Block. A CAS disagreement is never overridden by the generator.

The verifier runs on a different pinned model from the generator, and check (d) runs on no model at all. A verifier that shares the generator's weights shares its errors, and the correlated-failure mode is exactly the one that produces a confident wrong answer that passes its own check. What it makes harder: two vendor relationships to qualify instead of one, two regression surfaces under D22, and a second cost line per turn.

Decision D2714 September 2026

The gate-fire rate: the proportion of generated turns the verifier blocks. Not known and not guessable. It sets the cost of P2 twice over, once in wasted generation and once in learner experience, since every blocked turn is a question a free chatbot would have answered fluently. It is measured from the first frozen-battery run at M2 in 11 Roadmap, and it is the first number to look at when that run completes.

Figures are rendered, not generated

Diagrams are produced by deterministic rendering from a structured figure specification stored in the item bank, not by an image model. A number line, an axis pair, a labelled triangle and a function plot are all describable as data, and rendering them is a template.

Decision D2814 September 2026

Three constraints converge on this and any one of them would be sufficient.

  • Correctness. A generated image cannot be verified by the verifier. A figure rendered from validated data inherits the validation of the item, so visual_density in 02 can be a real style dimension without opening a hole in P2.
  • Cost. Image generation is the most expensive thing a turn could do. Rendering is effectively free, which is why the visual_density ceiling in 02 is a modest constraint rather than the dominant cost line.
  • Provenance. Verified The IT Amendment Rules 2026 require prominent labelling and permanent provenance metadata that cannot be stripped for synthetically generated information. A deterministically rendered figure carries its source item identifier in its metadata by construction. See 04.

What this costs: the figure vocabulary is finite, and a topic needing a figure type nobody has built is blocked on engineering rather than on content. The vocabulary needed for the Algebra strand is small, which is a further reason that strand is the launch scope.

Papers and grade ranges: deterministic, no model call

Practice papers and the provisional grade range are computed, not generated. Neither involves a model call, and that single property is what lets them inherit the item bank's validation instead of needing a verification story of their own.

ComponentInputMethodWhy it is not a model call
Paper assemblerThe paper's structural specification, plus live items with mark, command-word and difficulty metadata.Constraint satisfaction over the bank: hit the mark total, the coverage profile, the command-word mix and the difficulty distribution, excluding items the learner has seen recently.A generated paper would need every item verified afresh. An assembled paper contains only items that are already validated, so the paper's correctness is a property of the bank. T-PAP-01 checks the assembly, not the content.
Grade rangeMasteryState: unaided-check results on validated items.An arithmetic mapping from performance to a band, with an evidence-sufficiency gate below which nothing is shown.Asking a model to estimate a grade would produce a fluent, unfalsifiable number. An arithmetic mapping can be calibrated against real outcomes by T-CAL-01, and can be shown to be wrong.

The consequence worth stating: neither feature adds a cost line in 10, because neither consumes vendor tokens. They are close to free at the margin, which is unusual for the two features most visible to a paying parent.

Four details that are not obvious and are each doing work:

  • Preset.enabled is the entire kill switch. One boolean, read per request.
  • Session.preset_snapshot records the style object as it was at session start, so a transcript can be explained after a preset changes. For a licensed preset it is purged on the same seven-day line as the object itself, and the transcript thereafter carries only the neutral preset identifier. An earlier draft had the snapshot surviving termination as company work product; that is the exact retention the heads of terms rejects, and a snapshot that outlived the licence would have made the deletion promise false while appearing to keep it.
  • Turn.style_signatures is written at logging time, which is what makes T-STY-01 a measurement over live traffic rather than a separate test harness.
  • Account.verification holds a boolean and a reference. There is no date of birth field in this schema, anywhere, by design.

Kill switch mechanics

The service levels are in 04. This is what makes them achievable, and the fifteen-minute figure is a consequence of exactly one design choice repeated in several places: nothing derived from a persona is cached for longer than sixty seconds, and nothing derived from a persona is ever baked into an artefact.

The kill switch is rehearsed quarterly against a live archetype and the elapsed time is recorded. An untested switch is a claim, and this one is a contractual commitment to a creator. The rehearsal is cheap because D11 guarantees the product keeps running with the preset disabled.

Decision D2914 September 2026

Model choice and the vendor problem

Bought, pinned, abstracted, and qualified before use. No specific vendor is named in this document, for a reason that is not evasion.

Model prices, context limits and capability at the relevant tasks are not in the verified findings and are not stated here from memory. They change frequently enough that a number written today would be wrong before the item bank exists, and a plausible-looking cost per session built on a half-remembered price is exactly the kind of figure this repository is meant not to contain.

What to do instead: the selection procedure below is vendor-neutral and runs at M2, when there is a frozen battery to run it against. That is the point at which prices should be gathered and written into 10.

Unknownand deliberately not filled in

Selection procedure

  1. Gate on contract terms first. D24: zero retention of prompts and outputs, no training on our data. A vendor failing this is disqualified before quality is considered.
  2. Run the frozen battery T-REG-01 on each candidate and measure ACC-2, ACC-3, ACC-4, the gate-fire rate, and T-STY-01 conformance.
  3. Measure cost per session on the same battery, which is the only honest way to get the number.
  4. Pin the winning version. D22: a vendor update is a change that must pass the battery before reaching a learner.

Note the asymmetry the pinning creates, because it is a real cost. We will run behind the frontier, and we pay to qualify every upgrade. Verified The free tools are improving continuously and at no cost to the user, so running behind is a competitive expense as well as an operational one. It is accepted because the alternative is a vendor silently moving ACC-3 in the middle of exam term, which is the failure the entire correctness promise exists to prevent.

Cost per session, built up rather than assumed

The structure first, then the honest statement of what is missing.

cost_per_session
  = turns x [ generate(ctx_tokens, out_tokens)          // generator call
            + verify(node_tokens + assertion_tokens) ]  // entailment call
  + figures x render_cost                               // ~0, deterministic (D28)
  + cas_checks x 0                                      // local, no vendor cost
  + storage + telemetry                                 // negligible per session

where, per turn:
  ctx_tokens = system_fixed + style_card + k_nodes + window
                 |             |            |        |
                 |             |            |        +-- BOUNDED by rolling summary
                 |             |            +----------- BOUNDED, k fixed per objective
                 |             +------------------------ BOUNDED, fixed-size card
                 +--------------------------------------- fixed once written

The conversation window is a rolling summary of bounded size, not the full session history. Every term in ctx_tokens is therefore bounded, which makes cost per turn approximately constant rather than growing with session length.

This matters more than it looks. With an unbounded window, cost per session grows roughly with the square of the number of turns, and the sessions that cost the most are precisely the long ones with a struggling student, which is the student we most want to keep. A pricing model built on average session cost would then be wrong in the worst direction. What it makes harder: the tutor's recall of early-session detail is lossy, and the summariser becomes a component that can itself be wrong; it sits inside the content plane and its output is not citable evidence.

Decision D3014 September 2026: bounded context, therefore constant cost per turn

What can be said now without inventing anything: the only cost lever we control is bounded context multiplied by turns, every other term is a price someone else sets, and the architecture is shaped to keep both factors bounded. The arithmetic that follows from this structure, and its consequences for pricing, is in 10, which identifies the variable that actually dominates and finds that it is not this one.

What each choice makes harder later

The brief requires this and it is the section a future reader will want most.

ChoiceForced byWhat it makes harder
Deterministic retrieval before generation; the model never searches.P2, ACC-2.Open-ended questions are structurally hard. A learner asking something adjacent to the objective gets a refusal rather than an answer, and the product cannot grow into a general study assistant without dismantling this.
Separate verifier model (D27).Correlated failure.Two vendors, two regression surfaces, a second cost line, and latency added to every turn.
Figures rendered from specifications (D28).Verifiability, cost, provenance.A finite figure vocabulary. Subjects needing rich or irregular diagrams, which is most of science, need engineering before they need content. This is a real barrier to the second subject.
Bounded rolling window (D30).Constant cost per turn.Lossy recall within a session, and a summariser that can be wrong.
Pinned models, blocking regression (D22).Vendor drift during exam term.We run behind the frontier and pay to qualify every upgrade, while competitors get improvements free.
No fine-tuning, no adapters (D8).Revocability, the kill switch.Style fidelity is capped at what prompting achieves. If T-STY-02 fails and the diagnosis is fidelity, D8 forecloses the obvious fix and D6 exemplar conditioning is the only route left.
Zero-retention vendor terms (D24).The marketing-site line in 05.Narrows the vendor set, possibly to more expensive tiers, and forecloses vendor-side caching optimisations that would have cut cost.
Papers and grade ranges are computed, never generated (D28's principle, applied; D35 keeps the range ungated).Verifiability and cost.Item metadata (mark, command word, difficulty) must be right at authoring time, so a metadata error is now a paper defect rather than a cosmetic one. And a structural specification has to be written per board and per paper, which is the work that repeats if a second board is added.
No persona-dependent code paths (D11, T-ZERO-01).Zero-persona operation.Every persona feature must degrade gracefully to an archetype, which is a constraint on every future style feature, not a one-time check.

The row to watch is the first one. Deterministic retrieval is what makes the correctness promise enforceable, and it is also the thing that makes the product feel narrow next to a free chatbot that will cheerfully answer anything. That trade is the venture in miniature, it will show up as a retention problem before it shows up anywhere else, and 12 treats it accordingly.

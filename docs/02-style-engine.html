Style engine

Teaching style is represented as twelve numbers, each of which can be counted in a transcript and none of which belongs to anybody. A named educator becomes a point in that space, a student can move any axis from where the name put them, and a style that cannot be measured is treated as a claim rather than a feature.

Why a parameter object and not a prose description

Prose drifts. A paragraph describing how someone teaches captures register and loses structure, cannot be diffed between versions, cannot be tested for conformance, and has an uncomfortable relationship with the thing it describes. Twelve numbers can be audited, composed, adjusted one at a time, reproduced exactly, and are not a copy of anything.

This is decision D7 and it does four jobs at once.

  • It makes style testable. Each dimension has an observable signature that can be counted in a transcript. A style claim becomes a measurement rather than an assertion. That is the whole of conformance testing.
  • It makes style adjustable one axis at a time, which is what D10 requires and what prose cannot give you.
  • It makes the kill switch cheap. A departing creator costs a row in a registry. Nothing has to be retrained, which is D8, and nothing has to be rewritten.
  • It keeps the representation legally inert. The object contains no creator material. Every dimension is a fact about pedagogy that has been observable in classrooms for a century, and a vector of twelve integers is not expressive content. That argument is set out properly in 04, where it has to survive a lawyer.

The admission criterion for a dimension

A candidate dimension enters the set only if it passes all three tests. This is the rule that keeps the set honest as it grows.

  1. Countable. Two independent readers with the rubric, given the same transcript, produce the same number within tolerance. If scoring it requires taste, it is not a dimension.
  2. Pedagogically real. Changing it changes what the student is asked to do, not how it sounds. Tone dimensions are the failure mode; they produce the illusion of a style engine at a tenth of the cost and none of the effect.
  3. Unowned. It describes a choice any teacher makes. If a dimension can only be defined by reference to one person, it is a description of that person and it does not go in the set.

The parameter set, version 1

Twelve dimensions, each an integer from 0 to 100. Decision The seven dimensions named in the brief are all present; five were added because the seven did not span the differences visible in real teaching, and one of the additions is flagged as low-weight for a reason given below.

Warmth, encouragement rate and register are deliberately excluded from the twelve. They are the easiest dimensions to implement, the easiest to perceive, and they fail admission test 2: they change how a session sounds without changing what the student is asked to do. A style engine built on them would demonstrate beautifully and teach identically, and the D14 return-rate instrumentation would then be measuring nothing. Register is carried in the style card as free text for naturalness, is not scored, and is not adjustable by the student.

What this makes harder: presets will feel less distinct on a first read than they would if tone varied, which raises the risk that T-STY-02 fails for a reason that is real but not the reason we care about. That risk is accepted and noted in where this design is weak.

Decision D1714 September 2026: no tone dimension in the weighted set

From object to style card

The model never sees the object. It sees a style card, a block of text generated from the object by a deterministic, versioned renderer.

Determinism matters for three reasons that are not obvious: a card can be regenerated exactly from a stored object, so audit is possible; a card can be diffed when a preset changes; and when a licence ends, deleting the object removes every card that could be produced from it, because the renderer is the only path by which one comes into existence. That is a statement about production, not about retention: a rendered card and a fitted vector are also held in Session.preset_snapshot, which is why 06 deletes the snapshot on the same line.

render(object, renderer_version) -> style_card_text

The renderer maps each dimension to a band and emits the instruction for that band. Bands, not raw numbers, because a model follows "do not state the general rule until the student has worked at least two instances" far more reliably than it follows "formalism_latency: 88".

Rendered card for arch.groundwork · renderer cine.card/1.0.0

Teaching style for this session.

Open with a specific instance, never with the general rule. Use numbers or a situation the student can check for themselves in one step.

Do not state the general rule until the student has worked at least two instances and has attempted to state it themselves. If they state it imperfectly, accept the substance and restate it precisely once.

Carry one example through the whole session. Change the numbers in it rather than introducing unrelated new contexts.

When the student is wrong, do not correct them. Ask a question whose answer will show them the error, and let them say what went wrong. Correct directly only if the same error survives two attempts.

Stay concrete. Generalise only after several instances, and signal when you are doing it.

Use a figure where it carries the idea better than a sentence; roughly two thirds of explanatory moves should have one.

Ask more than you assert. The student should be producing more text than you are.

Use plain language before notation. Introduce symbols only once the idea they name is already understood.

Do not warn about common wrong answers in advance. Let the student meet them.

Show about half the steps in a worked solution and leave the rest to the student.

Register: plain, unhurried, second person.

Note what the card is not. It contains no creator's name, no quotation, no phrasing attributable to anyone, and nothing that could not have been written by a teacher trainer describing a lesson. That is a deliberate property and it is the one that makes 04 tractable.

How a named educator becomes a point in the space

The creator licenses name and likeness only. No creator material is ingested. The mapping below is therefore produced by people watching publicly available teaching and scoring a rubric. The material is observed, not ingested: nothing from it is stored, embedded, indexed or passed to a model.

Constraintdecision D5

That distinction is the whole ballgame and it is easy to blur under delivery pressure, so it is written as a procedure with a record rather than a principle.

The rating protocol

  1. Material. At least 120 minutes of publicly available teaching by the creator, spanning at least four distinct topics. Referenced by URL and timestamp in the provenance record. Not downloaded, not transcribed into the system, not retained.
  2. Raters. Three independent raters, each qualified to teach the subject, each scoring all twelve dimensions against the published rubric, working without sight of each other's scores.
  3. Aggregation. Per dimension, the median of the three scores.
  4. Reliability gate. Per dimension, agreement is computed across raters. A dimension that fails the agreement threshold is not guessed; it is set to the nearest archetype's value and flagged in the provenance record as unfitted. A preset with more than three unfitted dimensions is not shipped.
  5. Creator review. The creator is shown the resulting twelve numbers and the rendered card, and may object to any of them before the preset goes live. This is a term of the licence, not a courtesy; it is in the term sheet.
  6. Record. Provenance stores: rater identities, date, material URLs and timestamps, per-dimension scores and agreement statistics, the aggregated vector, the renderer version, and the creator's sign-off. It stores no creator content.

The agreement threshold. Setting it needs pilot data from three raters scoring the same material, which does not exist. Writing a number here would be inventing one. The threshold is set at M3 in 11 Roadmap from the pilot, and the pilot is the first place the rubric meets a real educator. Cost of getting it wrong: set too loose, presets are noise wearing a name; set too tight, no creator is fittable and the wedge cannot ship.

Unknownrequired input

That a recognisable educator's teaching is stable enough across topics to be a point rather than a cloud. A creator who teaches an introductory topic concretely and a hard topic formally is not one vector; they are a function of difficulty. If the pilot shows large within-creator variance, the representation needs a difficulty conditioning term and the schema changes. This is the most likely technical reason for the preset design to need rework, and it is cheap to test early, which is why it sits at M3 rather than later.

How a student moves an axis

D10. Picking a creator selects a preset; the student may then move individual dimensions. The handle gets them in, and then they can turn it.

  • Surface. Not twelve sliders. Six controls in plain language, each mapping to one or two dimensions, on a five-point scale, with the preset's position marked. "Tell me the rule first, or let me work it out" maps to entry_point and formalism_latency. "Correct me, or make me spot it" maps to error_response.
  • Scope. Adjustments are per student, per subject. They persist between sessions and there is always a one-tap return to the preset as licensed.
  • Privacy and the Online Safety Act. An adjusted style is visible only to the student who made it. It cannot be named, published, shared or sent to another user. This is not a product preference; it is the architectural invariant that keeps the service outside user-to-user territory, and the trigger analysis is in 05.
  • Attribution. Once a student has moved an axis, the on-screen label changes from "Style preset licensed from [Name]" to "Style preset: [Name], adjusted by you". A creator should not be shown as the author of a configuration the student invented. This is a rights point as much as an honesty point.

Acting on a creator objection within 14 days

The licence gives the creator a continuing right to require a specific behaviour to be removed within 14 days. That right needs a mechanism, or it is a promise with nothing behind it. There are exactly three, in escalating order, and none requires a release:

  1. Move a dimension. If the objection is to a teaching behaviour the vector produces, change the value.
  2. Add a constraint. The constraints field carries a never-do list that the renderer emits verbatim into the card. This is where "do not do X" lives when no dimension expresses X.
  3. Withdraw the preset. The kill switch, on the creator's word rather than ours.

All three are configuration changes to one record, which is what makes 14 days comfortable rather than tight. The constraint list is also the honest answer to a question the parameter set otherwise cannot handle: a creator may object to something that is not a point in the twelve-dimensional space at all.

Clamps

Not every point in the space is a legitimate tutor. Four dimensions are clamped and the student cannot cross the clamp.

visual_densityCeilingCost. Figures are the expensive part of a turn; the ceiling is an economics constraint and is set in 10.

Conformance testing

A style that cannot be verified is a claim, not a feature. Four tests. None has been run.

T-STY-03 is the one that protects the business. The failure it guards against is a tutor that, asked to be brisk and exam-facing, quietly starts cutting corners on correctness, or that under a concrete-first preset avoids the formal statement altogether and leaves the student unable to answer the examined question. Style is a presentation-layer variation over a fixed content plane, and T-STY-03 is what turns that sentence from an intention into a property.

T-STY-02 is the one that tests the venture. If a blind grader cannot tell two presets apart, then D4's wedge has no substance to sell, whatever students say in a survey. It is deliberately scheduled before any creator is signed, at M3 in 11 Roadmap, so that a failure costs an engineering cycle rather than a contract.

The D6 boundary: where exemplar conditioning attaches

One field, one renderer slot, one retriever. The seam is specified now so that exercising D6 is a configuration change plus a licence, not a rewrite under time pressure.

The interface

Exemplar conditioning attaches at exactly one place: the exemplars field of the style object, which is null in every shipped preset at launch.

// Launch (D5): always null.
"exemplars": null

// Under D6, and only with a content licence in force:
"exemplars": {
  "corpus_id":     "lic.creatorref.v1",
  "licence_id":    "CL-2027-0xx",
  "licence_expiry": "2028-06-30",
  "retrieval":     "objective_matched",   // k segments matched to the objective
  "k":             3,
  "max_quote_tokens": 0                   // set by the licence; 0 = no verbatim reuse
}

When the field is non-null, the renderer populates a slot that is otherwise omitted entirely:

render(object, renderer_version) -> style_card_text
  [dimension instructions from the twelve bands]     // unchanged
  [register note]                                    // unchanged
  [EXEMPLAR SLOT: present only if object.exemplars != null]

What changes when D6 is exercised

AreaChange
LicenceName and likeness is no longer sufficient. A content licence is required, covering reproduction, adaptation and machine processing of specified material, for a defined term. This is Schedule 2 of the heads of terms and it is drafted but unexercised.
StorageA licensed corpus store appears, holding creator material with per-segment provenance, licence identifier and an expiry that is enforced by the store rather than by a person remembering.
Kill switchGains two steps: invalidation of cached prompt fragments, and deletion of the corpus and every derived index. The 15-minute disable is unaffected; what slows and complicates is the deletion behind it, and the figures are in 04. This is the single largest operational cost of D6.
EvaluationT-STY-04 becomes live and blocking. A leakage failure is treated as a rights incident, not a quality bug.
LabellingThe on-screen line changes, because "does not write these answers" is harder to sustain when the creator's material is conditioning them. The revised wording is a counsel question, listed as OI-6 in 14.
Rating protocolExtended, not replaced. The twelve dimensions are still fitted by human raters; exemplars are additional, not a substitute.

What does not change

This list is the point of designing the boundary now.

  • The schema of the twelve dimensions, and every value fitted under it. Existing presets keep working.
  • The renderer interface and its contract. Only a slot is populated.
  • The student adjustment controls and the clamps.
  • The content plane: the item bank, retrieval, the verifier and the accuracy floor. Exemplars condition style and are never a source for a curricular claim. The verifier does not accept an exemplar as grounding.
  • D8 holds absolutely. No LoRAs, no fine-tuned weights, no adapters carrying creator style, under D5 or D6. Weights cannot be cleanly revoked and a kill switch that requires retraining is not a kill switch.

The exemplar retriever is specified to return objective-matched segments as style context only, and the verifier is specified to reject any curricular claim whose only support is an exemplar. Without that second half, D6 quietly reintroduces ungrounded content through the style path and P2 fails silently. The seam is designed so the content gate sits downstream of it and cannot be bypassed.

Decision D1814 September 2026

Where this design is weak

Four places, in descending order of how likely they are to matter.

  1. Nothing here has been fitted to a real person. The rubric, the twelve dimensions and the agreement threshold are all untested against an actual educator. The pilot at M3 is the first contact with reality and the schema should be expected to change.
  2. Excluding tone may cause T-STY-02 to fail for the wrong reason. Presets that differ only in structure are genuinely harder to tell apart on a single transcript than presets that differ in voice. If T-STY-02 fails, the first diagnostic is to check whether graders discriminate better on longer samples before concluding the wedge is dead. That check is part of the test design, not a reaction to a bad result.
  3. The within-creator variance problem described above could force a conditioning term, which would complicate the student controls and the licence review step.
  4. Twelve dimensions may be more than a language model reliably follows at once. A card with twelve instructions competes with the content instructions and the safety instructions in the same context. If T-STY-01 shows systematic drift on the low-salience dimensions, the fix is fewer dimensions with wider bands, not a longer card. That would mean version 2 of the set, and the set is versioned for exactly this reason.

Cost per session

Cost per session is not known and is not estimated here. It depends on how many turns a session has, which is not known: one question is a design target of three to six minutes (D112), "Keep going" extends it within the time cap set from PM3's pilot (D103), and the pace sets how many turns fit. It depends on the calls each turn makes, which for the Primer are recognition when the child speaks, triage, retrieval, the generator, up to eight verifier checks, the selection model and the voice. It depends on the explainers: for each, a script and its checks, video generation and the image check, unless a cached video serves. And it depends on the review at the close.

            + generate(ctx_tokens, out)    // pinned generator

            + select                       // the selection model (D124)
            + speak(spoken_length) ]       // the voice; D30 does not bound it
  + explainers x [ script + verify(checks) // written and checked like a turn
                 + video                   // generated live, unless cached (D122)
                 + image_check             // every video, before it plays (D126)
                 + speak(voice_over) ]     // the video's voice-over
  + review                                 // once, at the close (D107)
  + storage                                // the summaries, the per-turn log, the queues,
                                           // the flagged hold, the safeguarding count,
                                           // the escalation records and the video cache;
                                           // no turn of the child's, whole or in part,
                                           // after the close outside the read-back and
                                           // the kept question, except a flagged
                                           // exchange until its review closes (D104, D107)

where, per turn:
  ctx_tokens = system_fixed + wording_card + sources + summaries
             + child_words                 // this conversation, whole, until the close
             + window                      // the Primer's earlier turns, summarised (D30)

D30's bounded summary does not cover the child's words. The read-back and its check need what the child actually said, so the child's words stay whole in the window until the close, bounded by the time cap, and only the Primer's own earlier turns are summarised, as the ledger's note on D30 records. Cost per turn therefore grows with what the child has said, up to the bound the time cap sets; how large the child's words grow is Unknown until PM4.

Two things are already clear without a number: each Primer turn makes more calls than a Tutor turn, and speech and live video each add a cost that grows with use, video's with every explainer a cached copy does not serve.
